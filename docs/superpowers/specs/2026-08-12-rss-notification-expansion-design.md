# RSS通知拡張 設計仕様

## 目的

現在のYouTube Atom RSS通知を、同じ運用モデルの汎用RSS/Atom通知へ拡張する。YouTube Data API、Cookie、WebSub、外部データベースは追加せず、現在のDiscord BotとFly.io上の単一プロセスで動作する範囲に限定する。

対象は、現在の5つのYouTubeチャンネルを維持しながら、Qiita、Reddit、GitHub Releases、ブログなどの公開RSS/Atomフィードを追加できること、新着通知をキーワードで絞り込めること、運用状態をDiscordから確認・一時停止できることである。

## 採用方針

### 設定

フィード定義は `RSS_NOTIFICATION_FEEDS` 環境変数のJSON配列で受け付ける。未設定の場合は、現在のYouTube 5チャンネルを組み込み既定値として使用する。

各フィードは次の形式とする。

```json
{
  "name": "sana_natori",
  "url": "https://www.youtube.com/feeds/videos.xml?channel_id=UCIdEIHpS0TdkqRkHL5OkLtA",
  "include": [],
  "exclude": []
}
```

- `name`: Discord上で表示する一意な名前
- `url`: `http://` または `https://` のRSS/Atom URL
- `include`: タイトルに1語でも含まれる記事だけを通知するキーワード配列。空配列は全件対象
- `exclude`: タイトルに1語でも含まれる記事を除外するキーワード配列

設定不正のフィードはBot全体を停止させず、ログと `/status` にエラーを出して無効化する。組み込みYouTubeフィードは、既存環境変数なしでも動作するよう維持する。

### 取得・解析

新しい `rss_notifications.py` に、次の責務を集約する。

- RSS 2.0 と Atom の記事解析
- フィード設定の検証とキーワードフィルタ
- フィード単位の新着判定
- Discord通知文の生成
- フィードごとの成功・失敗状態の保持

RSS/Atom記事の識別子は、Atomでは `yt:videoId`、`<id>` の順、RSSでは `<guid>`、`<link>` の順で決定する。識別子がない記事は安全のため通知対象外とする。

各フィードは5分ごとに並列取得する。1フィードのHTTP/XMLエラーが他フィードの通知を止めないよう、フィード単位で成功・失敗を処理する。HTTPタイムアウトは20秒とする。

### 重複排除と再起動

重複排除はプロセスメモリ上のトラッカーで行う。Bot起動後の最初の成功取得は現在状態のベースラインとし、既存記事を一括通知しない。通知送信に失敗した記事は、次回取得時に再試行できるようトラッカーから戻す。

Fly.ioの永続ボリュームや外部DBは現段階では導入しない。そのため再起動後の過去記事の永続的な重複防止は今回の保証対象外とし、仕様書・READMEに明記する。

### Discordコマンド

既存コマンドと衝突しない `/rss` コマンドグループを追加する。

- `/rss list`: フィード名、URL、稼働状態、フィルタ概要を表示
- `/rss pause name`: 指定フィードをプロセス内で一時停止
- `/rss resume name`: 指定フィードを再開
- `/rss test name`: 指定フィードを取得し、最新記事の通知形式を本人のDMへテスト送信

`pause`、`resume`、`test` は `DIARY_OWNER_USER_ID` と一致するユーザーだけが実行できる。所有者ID未設定時はRSS通知タスクとコマンドを無効化する。環境変数のフィード定義を変更した場合はBot再起動で反映する。

### 状態表示

既存の `/status` にRSS全体の有効数と、フィードごとの次の状態を追加する。

- 有効/一時停止
- 最終成功時刻
- 連続失敗回数
- 直近エラーの短い内容
- 直近の通知件数

フィード取得に失敗しても既存の `/status` 自体は成功させる。エラー本文は最大長を制限し、Cookieやトークンなどの環境変数値は表示しない。

## 通知形式

通知は現在と同様に、1回のポーリングで見つかった複数記事を1件のDMにまとめる。

```text
📡 RSS新着通知

フィード名
記事タイトル
URL
```

Discordのメッセージ上限を超える場合は記事単位で切り詰め、切り詰めた件数を末尾に表示する。フィルタで除外された記事は通知せず、同じ記事を後のポーリングで再通知しない。

## エラー処理

- XML解析エラー: 該当フィードだけ失敗扱いにする
- HTTPステータスエラー・タイムアウト: 該当フィードだけ失敗扱いにする
- Discord DM送信エラー: そのポーリングの新着記事を再試行可能な状態に戻す
- フィード設定エラー: 該当フィードを無効化し、起動時ログと `/status` に表示する
- すべてのフィードが失敗した場合: タスクエラーを記録するが、Discord Botは稼働し続ける

## テスト方針

外部ネットワークと実Discord DMには接続しないユニットテストを追加する。

- Atom（YouTube要素を含む）の解析
- RSS 2.0の解析
- 識別子がない記事の除外
- フィード設定のJSON検証と既定値
- include/excludeフィルタ
- 初回ベースライン、二回目の新着、重複、送信失敗後の再試行
- 1フィードの失敗が他フィードを止めないこと
- Discordメッセージ長の切り詰め
- `/rss` コマンドの所有者ガードと状態表示

既存の全テスト、`py_compile`、`git diff --check` を実装完了時に実行する。

## 非対象

- YouTubeライブ開始の厳密な検知
- YouTube Data API、Cookie、WebSub
- RSS通知状態のSQLite・Scrapbox・外部DBへの永続保存
- Webダッシュボード
- RSS記事本文の取得・要約・Scrapboxへの自動保存
