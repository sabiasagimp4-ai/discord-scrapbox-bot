# YouTube RSS新着動画DM通知 設計

## 目的

指定した5つのYouTubeチャンネルに新しい動画または配信ページが追加されたとき、既存のDiscord Botから `DIARY_OWNER_USER_ID` のユーザーへDMを送る。YouTube Data API、Cookie、ライブ状態の厳密な判定は使用しない。

## 通知仕様

- 監視対象は次の5チャンネル。
  - sana_natori: `UCIdEIHpS0TdkqRkHL5OkLtA`
  - gerrardon: `UCRaaCxSF8nEpfG3ZHesXKxw`
  - れてんジャダムの反省: `UCrEqTsfWfvXpbRnXyiUr2UQ`
  - じゃだれてセンチメンタル: `UC0qYZ6Z1AXghnEHZ8IEWtLg`
  - 既指定チャンネル: `UC4Kt3OCvmHXhysdW8VU_P6A`
- YouTube Atomフィードを5分ごとに取得する。
- フィードに現れた動画IDを新着として扱い、タイトル・チャンネル名・URLをDMする。
- ライブか通常動画かの判定は行わない。ライブ配信ページがフィードに現れた場合は、新着コンテンツとして通知する。
- Bot起動後の初回取得は現在のフィードを基準値として保存し、過去動画を一括通知しない。
- 同じ動画IDは一度だけ通知する。
- RSS取得失敗時はその回の比較と通知を行わず、既知IDを失わない。既存のタスク記録・エラーログへ失敗を記録する。

## 実装方針

- `requests`でAtom XMLを取得し、標準ライブラリのXMLパーサーで解析する。新しい外部依存は追加しない。
- 5チャンネルを1つのDiscordタスクで順に取得し、取得結果をまとめて処理する。
- DM送信は既存の `_fetch_with_retry` と `client.get_user` / `client.fetch_user` のパターンを再利用する。
- 通知先の `DIARY_OWNER_USER_ID` が未設定の場合は機能を無効化し、Bot全体は起動できるようにする。
- 通知状態は現行の他の定期通知と同様にプロセス内メモリで保持する。再起動後はRSSの現在のエントリを基準値にするため、再起動直後に過去通知は行わない。
- フィードのHTTPキャッシュにより通知が遅れる可能性がある。5分間隔はアプリ側の確認間隔であり、YouTube側の配信遅延を保証しない。

## DM形式

チャンネルごとに、次の情報を含む短いメッセージを送る。

```text
📺 YouTube新着通知
チャンネル名
動画タイトル
URL
```

同一ポーリングで複数動画が見つかった場合は、動画ごとにDMを分けず、1通にまとめる。

## テスト方針

- Atomフィードの正常解析、名前空間、空フィード、壊れたXMLをテストする。
- 初回基準値作成、差分検知、重複排除、複数チャンネルの集約をテストする。
- DM先未設定、取得失敗、DM送信失敗をテストする。
- ネットワークへ接続しないモックテストとし、実際のDiscord DMは実行しない。

## 代替案を採用しない理由

- YouTube Data API: 今回は使用しない方針。
- Cookie付きページ監視: 認証情報の管理が必要で、YouTubeのHTML変更にも弱いため採用しない。
- WebSub: 動画公開を高速化できるが、外部公開HTTPSコールバックと購読更新の運用が追加になるため、今回は既存Bot内で完結するRSSポーリングを優先する。
